# 浏览器验收与交付

## 证据分类

| 类别 | 能证明 | 不能证明 |
| --- | --- | --- |
| 生成设计稿 | 视觉目标与构图 | 产品运行、交互或后台能力 |
| 真实运行截图 | 当时渲染、数据和状态 | 单靠截图不能证明按钮/接口有效 |
| 隔离状态示例 | 受控长内容/初始化等布局 | 真实模型输出或账号初始化 |
| 自动检查 | 已执行的构建、操作与断言 | 用户视觉接受、其他设备/付费服务 |

目录、文件名和图册标签注明来源。README 用真实运行截图展示产品，示例另列；不能用生成稿覆盖截图再写真实前端。

## 浏览器检查

采用可用的 Playwright、浏览器桥接或其他驱动，不依赖固定插件。启动项目真实 HTTP 服务与后端，确认 URL，不双击 React/Vite 入口 HTML。

按变更抽样检查：

- 参考视口的构图、侧栏、头像比例、图标、输入框和人物遮挡。
- 空白/有内容、代码/长文本、文件面板、表单、弹窗、错误与禁用。
- 移动窄屏、侧栏收起/抽屉、宽桌面及 200% 缩放。可抽样 320/390/768/1440 或已有断点，不规定固定套数。
- 导航、键盘焦点、Escape 返回、点击区域、滚动、输入和快捷入口，避免填草稿误变为自动发送。
- 主题切换、系统主题监听、减少动态；离线与加载按相关功能测试。
- pageerror、图片解码、404、横向溢出与受影响请求。

用现有测试账号、隔离环境或获准初始化流程。读操作和写操作分清：创建管理员、发消息、写工作区、付费调用需要相应授权，不重置现有后端为截图首次初始化。

等待字体与必要图片加载，固定视口和状态，减少动态。只读 fixture 响应注明来源，不拦截写操作制造保存成功；无真实模型/渠道凭据时保留未配置状态。

## 比较与修正

顺序为构图空间、材料外形、字体层次、状态响应。修正后重测受影响检查；纯素材替换无需写镜像实现的单元测试，认证/表单等行为修改需要有意义的回归。不要无理由重跑全部耗时测试。

每次反馈落到具体部件：问题 → 本次改动 → 同视口/主题/状态截图 → 用户结论。先解决“工作区文字偏了”“设置与装饰重叠”等明确问题，不把一次局部调整变成整页再设计。主动优化在独立改动中保留前后对照，用户反馈比抽象美学评分更有决定性。

用户说回退时，恢复对应视觉改动与已选素材，保留无关功能修复和用户编辑；先看 diff，不直接 hard reset。已取消方向的生成结果即使稍后返回，也不能自动应用。用户移除的人物区、头像或文案不得在后续美化中复活。

“完整版”逐项对照最初页面/状态矩阵：主要路径可用，空白、加载、失败、长内容与窄屏有交代，启动方式可复现。概念图、首页截图或构建成功不能代替这些结果。缺少外部凭据时列明未验证路径与配置入口，不给虚构账号或把示例回复写成联调成功。

## 来源与提交检查

公开分发素材时，沿用项目现有 NOTICE、README 或素材清单，避免另造登记系统。至少能追到：

| 项目 | 如实记录 |
| --- | --- |
| 创作分类 | 原创绘制、AI 生成、授权素材或改作；不只写“贡献者提供” |
| 来源证据 | 原作者/稳定来源页；AI 服务名称、现存生成记录与参考输入；缺失项标未知 |
| 权利范围 | 素材和角色/作品分别说明，公开再分发、商业使用与代码许可分别记录 |
| 可见声明 | 按目标仓库要求放到指定语言的 README/NOTICE，不能只藏在机器清单里 |

用户确认“可公开使用”是授权陈述，AI 生成是创作方式；两者都不能单独证明第三方角色权利已获清理。来源检查、许可确认和法律核验分别表述，没有相应证据不写“已完成版权核验”。不要因删除作品名就把历史参考写成完全无关原创，也不要替贡献者扩大法律保证。若保留受保护角色，按当前收录规则列出角色/作品/权利人及要求的非官方、非商业、无关联和异议处理声明；信息不明先核实。不要伪造生成服务、原作者、请求号或证据链接。

先完成可独立推进的本地实现；缺少公开分发依据只阻止相应资产的发布。可以准备不含该资产的包、接受新证据，或在用户选定后替换独立设计，不能静默换掉已锁定原图。

涉及目标项目提交时，读取当前 CONTRIBUTING 与开发文档；沿用标准脚手架、命名和门禁。例如 DSH 皮肤先核对 dsh-skins 当前规则，再使用其皮肤脚手架与实际检查命令；不要把 dsh-web 的全部命令无条件套给独立皮肤仓库。UI 变更附真实验证截图或适当测试；提交信息遵守 Conventional Commits 及目标仓库其他约束。

## 图册与发布

需要双击图册时，做自包含静态页，分别展示设计、真实截图与素材，验证图片解码、放大和键盘关闭。应用继续通过 HTTP 启动，图册不是产品。

说明改了什么、为什么、实际构建/浏览器检查、未验证外部集成和待审阅图。不要发布账号、密钥或内部日志。

上传已授权时，核验目标仓库、隐私状态与分支，正常提交推送；只有当前提交的 CI 才能作为通过证据。不能自行公开私有项目，或从技能仓库许可证推导第三方图片的公开授权。

CI 失败先读日志，区分变更回归、既有失败与基础设施故障；授权范围内有限重试。不能为通过而删断言、随意延长超时或更换整机运行环境。审批服务连接错误不等于动作被判不安全；自动审批明确拒绝则说明动作与原因，再走允许的替代路径。

最终分别说明本地文件、已推送提交、当前 CI、已安装版本与市场收录的实际状态，只列本次适用项。关闭 PR 不会删除公开 Git 历史，推送也不等于上游已合并或市场已发布。
