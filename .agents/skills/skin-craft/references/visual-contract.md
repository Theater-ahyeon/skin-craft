# 视觉契约与页面覆盖

使用项目已有记录或短文档，不要求大型蓝图。用户的新反馈只更新受影响选择，无需重问已确定问题。

## 参考权重

| 项目 | 记录内容 |
| --- | --- |
| 主参考 | 艺术语言、角色、材料和核心构图 |
| 辅助参考 | 消息密度、文件工作区、表单等布局 |
| 锁定资源 | 要求直接使用的原图/动画和校验值 |
| 已拒绝 | 不再进入运行清单的版本及问题 |
| 允许变换 | 裁切、蒙层、无损编码或尺寸变换，按授权记录 |
| 未决项 | 真正影响下一步且不能推断的问题 |

主参考相同不意味着每页布局相同。完整屏幕图、概念板、说明板和素材包承担不同作用。注释、色板和放大状态通常放到设计图册。

## 多角色的身份与位置

按用户明确说明建立“角色编号 → 对应图片 → 身份关系 → 出现场景”的映射。分别记录实际可见的发型、服饰轮廓与标志配件；缺图时只记录文字关系，不编造长相。

以用户提供的 Maid Atelier 构思为例：图 1、图 2 是两位不同的女仆，分别保留特征并用于对话主体背景；图 3、4 可视为同一人。Q 版适合展开侧栏及局部装饰，但它对应哪两张图、是否是某位主体的 Q 版，需要依据实际图片或用户说明，不能仅凭文字猜测。两位女仆与 Q 版的身份关系不自动合并。

生成和验收逐人对照，避免复制同一张脸、混合服饰或把 Q 版当成普通缩小图。折叠侧栏和移动界面另定展示策略，不把完整人物压成窄条。

## 选定完整概念

一个主屏概念先确定人物与交互空间，再为确有不同需求的状态补稿。选择同时看审美与可行性：正文和输入区是否有空间、素材能否拆分、角色焦点能否在真实侧栏/详情宽度下保住、窄屏如何收纳装饰。无需为每页重新生成人物。

保存所选稿、选择依据和允许变化的部分。局部反馈不自动开启全新艺术方向。参考链接失效时寻找已授权副本或请求补图，区分用户描述与已实际查看的内容。

## 从源码建立矩阵

| 路由/组件 | 关键状态 | 设计来源 | 真实数据入口 | 验证 |
| --- | --- | --- | --- | --- |
| 工作台 | 空白/有消息/代码/侧面板 | 主参考 + 消息布局 | 现有 API/store | 操作 + 截图 |
| 配置表单 | 新建/编辑/错误/保存 | 统一组件材料 | 现有表单/API | 按授权测试 |
| 其他真实页面 | 对应空白与内容状态 | 同一视觉语言 | 实际源码 | 对应路由检查 |

不为未实现功能制作“已交付”页面。全套设计覆盖矩阵中的真实页面与核心状态，复用页面壳和表单减少生图次数。缺后端状态时可明确标记隔离示例，不冒充真实截图。

## 可测量的还原

把高度还原拆成：背景与人物、版面关系、页头/侧栏尺度、边框、材料、字体层级、状态与交互。记录项目视口，不把案例的 288px 侧栏/66px 页头当作通用尺寸。

原图不变用源文件和解码像素证据；文字、动态数据、屏幕比例、字体与生图文本仍有差别。如实说明已对齐项与待审阅差异，不用自动像素分数代替视觉判断。

## 版本与路径

可用 `docs/design/references/`、`docs/design/generated/`、运行资源与截图目录，优先已有结构。记录源图、提示词/回执、运行文件和组件对应关系。更新资源引用，不在每页复制不受控背景。

临时附件或授权 Wallpaper 源复制到工作参考目录，不写回壁纸或修改 Steam Workshop。源图权利与公开范围和代码分别记录。
